# 접합부 관통 슬릿 제거 — 최종 V3

`ERGO_HOUSING_25_WRAP_FINAL_V2` 에서 **팔받침 ↔ 조이스틱 블록 접합부의 관통 슬릿만**
제거한 버전이다. 경사 25° / 랩 스커트 / 폭 133.6 / 동결 코어 / 캐리어 인터페이스는
전부 그대로다. Onshape API 호출 0건.

이전 버전 `ERGO_HOUSING_25_WRAP_FINAL_V2` 는 **삭제하지 않고 보존**했다.

---

## 1. 구멍의 정체

사용자가 슬라이서 화면에서 좌우 대칭의 흰 슬릿을 지적했다.
렌더를 믿지 않고 세 가지를 따로 쟀다.

```
실루엣 관통 감사   앞 0도   5.2 mm2 (측정 아티팩트)   앞 부각30도  43.2 mm2  ← 진짜
짐벌 노출          앞 0도   0.2 %                    ← 짐벌이 보이는 건 아니다
수직 광선 스캔     X 58~66.8 구간의 재료 최상단 Z
                   Y <= -13 (램프)  -63.6 ~ -72.9
                   Y >= -13 (블록)  -129  ~ -137
```

**원인: 팔받침 램프 단면이 `y_rear = anchor[0] + 5.0` = Y −15 에서 끝난다.**
거기서 바깥 폭이 **133.6 → 113.0 으로 10.3 mm 급히 꺾이고**, 램프의 둥근 코너와
블록의 평면이 만나는 모서리에서 서로 닿지 못해 초승달 관통 슬릿이 남았다.
좌우 대칭인 이유가 이것이다.

> 정면(0°)·측면(0°)·ISO 에서는 짐벌 노출이 0 % 다. 슬릿은 **부각 20~40°** 에서만 보인다.
> 첫 라운드에 내가 `FRONT` 로 렌더한 방향(w = −UH)은 팔받침 **반대쪽**이었고,
> 그 때문에 "정면에 구멍 없음" 이라고 잘못 보고했다. 팔받침 쪽에서 봐야 보인다.

## 2. 폐기한 두 가지 시도

### 시도 1 — 스커트 상단을 덱까지 (`sk_top` −140 → DECK)

```
부피 997,304 -> 1,762,931 mm3 (+77 %)   shells 3
```
스커트를 덱에서부터 통짜로 내리면 **하우징 중공까지 채운다.** `prot`(CAVITY_PROTECT)는
짐벌 공동만 보호하고 셸 내부(약 3,027,000 mm3)는 보호하지 않는다.

### 시도 2 — 램프 단면을 하우징 뒤끝까지 연장 (`y_rear = hb.max.Y + MARG`)

```
부피 1,029,571 mm3   관통 43.2 -> 147.5 mm2 (악화)   23게이트 FAIL 1
```
연장한 단면이 만든 외피가 **동결 코어에서 8.3 mm 떨어진 이중벽**이 됐다.

```
Y=+60, Z=-86  +X 광선 교차점:  31.0  54.0 | 62.3  66.8
                              └ 코어 벽 ┘  └ 새 외피 ┘   ← 8.3mm 빈 공간
```
단면 상단 코너가 라운드라 Z −68~−74 에서 그 공간이 열려 더 큰 관통이 됐다.
모션 FAIL 은 늘어난 덱 캡이 개구부 뒤 가장자리를 먹은 것 —
충돌 4점이 전부 **Y +64.1~64.7, Z −61.92~−61.95 (덱 평면)** 이고,
덱에서의 스윕 포락선 한계 Y +64.85 를 0.2~0.7 mm 침범했다.

## 3. 채택 — 폭 블렌드

램프 폭을 접합 구간에서 **하우징 자체 폭(113.0)까지 부드럽게 좁힌다.**

```python
W_BLOCK = 113.0
f_end = W_BLOCK / pad_width          # 113.0 / 133.6 = 0.846
if slope_blend and yk > y_front_body:
    g = (yk - y_front_body) / (y_rear - y_front_body)
    w = 1.00 + (f_end - 1.00) * g
```

```
Y -227.2 (팁)      90.8 mm   (0.68)
Y  -81.8 (앞끝)   133.6 mm   (1.00)   <- V2 에서 맞춘 접합부 일치 유지
Y  -15   (램프 끝) 113.0 mm   (0.846)  <- 하우징과 동일 -> 단차 0
```

램프가 끝나는 지점에서 폭이 같아지므로 단차가 **물리적으로 생길 수 없다.**
이중벽도 안 만든다. 겹치는 67 mm 구간이 턱이 아니라 테이퍼가 된다.

## 8. 교훈

1. **부품별로 그리는 렌더는 거짓말을 한다.** 나중 부품이 하우징 위에 덧칠돼
   짐벌이 비쳐 보였고, 나는 그걸 "구멍" 으로 읽었다. 전 삼각형을 합쳐 **한 번만**
   깊이 정렬해야 한다.
2. **`FRONT` 라는 이름을 믿지 말 것.** `w = -UH` 는 팔받침 **반대쪽**이다.
   방향은 형상(팔받침이 −u 쪽)에서 유도해 확인해야 한다.
3. **구멍을 메우는 방향(살 추가)은 대개 틀린다.** 두 시도 모두 살을 더했다가
   중공을 채우거나 이중벽을 만들었다. 실제 해법은 **단차를 없애는 것**이었다.
4. 광선 교차점 목록(`31.0 54.0 | 62.3 66.8`)이 이중벽을 한 줄로 드러냈다.
   부피·shell 개수만으로는 못 봤다.
