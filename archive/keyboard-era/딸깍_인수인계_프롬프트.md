# 컨텍스트: 제7회 국립재활원 보조기기 해커톤 · 팀 「딸깍」

너는 이 프로젝트의 설계·문서 작업을 이어받는다. 아래는 2026-08-09 시점까지 확정된 내용 전부다.
**여기 적힌 것이 최신 확정본이며, 이전 문서(README·설계구체화 v1·누운자세 구체화 md)에 다르게 적힌 부분은 폐기된 것으로 간주한다.**

## 0. 프로젝트 한 줄

**한 손의 잔존 손가락 움직임으로 키보드와 마우스를 통합 제어하는 고정형 입력장치.**

- 대회: 제7회 국립재활원 보조기기 해커톤 · '컴퓨터 및 전자기기 접근성 보조기기' 부문
- 팀: 딸깍 — 김민섭(팀장) / 윤홍민 / 장재원 / 김예진, 전원 동국대 전자전기공학부
- 팀 역량: ESP32·ATmega 기반 임베디드 설계, FSR·로드셀·MPU6050 센서 로직, UART/무선 통신,
  ESP32 기반 PCB 설계 + 듀얼 버튼·마이크·스피커 통합 시제품 완주 경험
- 최종 목표: 3D 도면과 펌웨어 공개 → 사용자가 저비용으로 직접 제작·개조

## 1. 문제 정의 (확정)

**병목은 "키를 적게 누르는 것"이 아니라 "팔을 들어 입력면에 접근하고 키보드↔마우스를 반복 이동하는 것"이다.**

대상 사용자 2군:

| 군 | 질환·상태 | 환경과 병목 |
|---|---|---|
| 기존 | 뇌졸중 후 편마비 · 상지 절단 · 뇌성마비 | 책상 환경. 한 손이 키보드-마우스를 왕복 → 문자 입력과 커서 제어를 동시에 못 함 |
| 추가 | 신경근육질환 · 척수손상 | 전동침대에서 반누운 자세. 팔을 들어 키보드 위에 유지 불가, 침대엔 장치 둘 평면 없음, 자세 바뀔 때마다 재정렬 필요 |

명시 제외: **손가락의 신뢰할 수 있는 움직임이 없는 사용자는 1차 대상이 아니다.**

기존 대안의 한계 — ① 표준 입력장치: 손 이동 자체가 반복 부하, 드래그·조합 단축키 사실상 불가.
② 상용 한 손 키보드: 포인팅이 없어 왕복 문제 잔존, 고가·국내 유통/AS 제한.
③ 소프트웨어(화상 키보드·마우스키): 설치·설정 권한이 필요해 회사·학교·공공기관 PC에서 사용 불가.

## 2. 페르소나 (확정 — 이전 47세 뇌졸중 편마비 페르소나는 폐기)

**허교환 · 35세 · 신경근육질환.** 재택으로 온라인 상품 정보 검수·문서 업무.
하루 4~6시간 컴퓨터 사용, 대부분 전동침대에서 상체 10~30° 세운 반누운 자세.
오른팔을 들거나 옆으로 이동하기 어렵지만, 팔·손목을 받쳐 주면 오른쪽 손가락으로 작은 굽힘·누르기 반복 가능.
시력·청력·인지·발화에 문제 없음.

- 어려움: 키보드↔트랙볼 짧은 거리도 혼자 반복 이동 불가 / 침구 기울기로 장치가 밀리고 각도가 달라짐 /
  손목·팔을 공중에 유지 못 해 장시간 작업 중단 / 화면을 보면서 손가락이 닿는 키 위치를 확인 못 함
- 요구: 별도 드라이버 없이 표준 키보드·마우스로 인식 / 침대 각도가 바뀌어도 장치 방향 조정 가능 /
  좌우손·손가락별 가동 범위에 따라 키맵과 활성 힘 변경 가능 / **설정 변경을 보호자가 아니라 본인이** 수행
- 목표: 보호자의 재배치 없이 **90분 이상 연속 작업, 분당 100타 이상**, 재택 근무자로 정식 복귀

## 3. 하드웨어 구조 (확정)

**인체공학적 버티컬 폼팩터 + 트랙볼 기반 통합 제어. 밀어서 움직이는 마우스가 아니라 고정형 본체.**

- **본체**: 수직으로 세워진 형태. 컵을 쥐거나 악수하듯 손을 얹어 밀착. 손목 회내(pronation) 방지.
  침대 사이드레일 · 침대 테이블 · 별도 관절형 암에 **고정**.
- **지지부(신규)**: 전투기 조종간처럼 본체 전체를 좌우로 기울여 **BANK A/B 전환**.
  손등 밴드 또는 측면 가이드로 미끄럼·이탈 방지.
- **엄지 영역**: 최상단 트랙볼(커서 360° 제어) + 바로 아래·옆에 좌/우클릭 택트 스위치.
  비선형 감도 곡선, 사용자 단계 조정 가능.
- **네 손가락 영역**: 검지~새끼 손가락 끝·마디가 닿는 3차원 곡면에 **토글 스위치** 배치.
  (※ 이전의 5-way 스위치 안은 폐기)
- **손바닥 반대 영역**: 엄지를 아래로 내려 누르는 동작으로 SPACE·SHIFT·CTRL·ALT 및 모드 전환.

**BANK / 입력 예산 (확정)**

```
좌로 4~5° 기울임 → BANK A       우로 4~5° 기울임 → BANK B
손을 놓으면 스프링 중앙 복귀, 선택된 BANK는 유지, LED 색상 + 짧은 진동으로 표시
토글 1개 = 위로 밀기 / 누르기 / 아래로 밀기 3동작
4개 토글 × 3동작 = BANK당 12키, + 엄지 보조키 1 = BANK당 13키
4 × 3 × 2 + 2 = 총 26키
MODE 키: 영문 → 한글 → 숫자·기호 순환
```

**제어부: Seeed XIAO nRF52840 Plus** (※ 신청서 원본의 ESP32-S3에서 변경됨. 설계 md의 "ESP32-S3 유지 권고"는 폐기).
USB-C 유선 + BLE 무선 동시 지원, USB-C가 배터리 충전 겸용.
**연결: OS 표준 HID 복합 장치(키보드+마우스). 드라이버·전용 프로그램 설치 불필요.**

디자인 레퍼런스: Azeron Cyborg II (게이밍 키패드 구조를 지지부 설계 출발점으로 참고).

## 4. 설계 심화 — 수정본과 충돌하지 않아 그대로 유효한 것

### 4-1. 엄지 자원 충돌과 해법 (중요 — 심사 대응 논거)

엄지 하나가 트랙볼·클릭·모디파이어를 모두 맡으면 **드래그**(좌클릭 유지 + 볼 굴리기)와
**Ctrl/Shift+클릭**이 물리적으로 불가능하다. 해법 3종 전부 적용:

1. **드래그 락** — 좌클릭 더블탭 = 눌림 유지, 이동 후 한 번 더 탭해 해제. 상용 트랙볼(Kensington·Elecom)에 있는 검증된 방식.
2. **원샷 모디파이어(OSM)** — Ctrl 탭 시 다음 입력 1개에만 적용 후 자동 해제. 더블탭 = 잠금, 3번째 탭 = 해제.
   Windows 고정키와 결과는 같지만 **OS 설정을 건드리지 않아** "설치 권한 없는 PC" 원칙을 유지.
3. **역할 분리** — 엄지는 포인팅 전담, 네 손가락은 문자·기능 전담.

### 4-2. 한글 입력 경로 (심사 1순위 질문의 답)

```
토글 입력 → 펌웨어 상태머신 → 자모 확정(확정 지연 버퍼) → 두벌식 스캔코드 → OS IME가 음절 조합
                                                        └ 여기부터 완전한 표준 HID
```

- **장치는 IME를 흉내내지 않고, IME에게 두벌식으로 말을 건다.** 이것이 "드라이버 불필요"의 실제 근거.
- **확정 지연(Commit Delay)**: 모음이 확정될 때까지 스캔코드 방출 보류. 다음 자음이 오거나 유휴시간(기본 400ms)이 지나면 한 번에 방출.
  → IME 조합 중 백스페이스 동작이 OS마다 다른 문제를 **회수를 아예 안 하는 방식**으로 회피.
- 한/영 전환: HID `LANG1`(0x90) 등 OS 기본 경로 사용.
- ※ 배열은 **미확정**. 이전에 검토된 천지인 파생 배열과 Half-QWERTY 안은 수정본(토글 3동작 × 2 BANK = 26키 구조)에서
  전제가 달라져 **다시 설계해야 한다.** 26키 예산에 맞춘 한글/영문 배열이 현재 최대 공백.

### 4-3. 누운 자세가 바꾸는 조건과 거치 설계

| 바뀌는 조건 | 대응 |
|---|---|
| 중력 방향이 90° 바뀌어 자중+논슬립 고정이 무효 | **클램프 암**을 침대 프레임에 상시 고정 |
| 손이 시야에서 사라짐 → 블라인드 조작이 전제 | 촉각으로 상태를 알 수 있는 배열 필요, 눈으로 레이어 확인 불가 |
| LED가 시야 밖 | **햅틱(진동) 또는 짧은 비프음** 패턴으로 대체 (코인 진동모터 ≈1,500원) |
| 케이블이 얼굴·목 위를 지나 위험 | **BLE 우선**, USB-C는 충전·설정용 |
| 체위 변경(통상 2시간 간격)마다 재설치 필요 | **자석 원터치 탈착** + 손등 스트랩 |

> 이 사용자군의 진짜 실패 지점은 성능이 아니라 **'부탁의 횟수'**다.
> 설계 목표: **한 번 설치하면, 체위 변경 후 사용자가 혼자 사용 자세로 복귀할 수 있어야 한다.**

### 4-4. 검증 계획 — "분당 100타"를 증명하는 법

'타' = 한국 타자 검정 기준 자모 1타. 한글 1음절 ≈ 자모 2.7개, 자모당 평균 입력 ≈ 1.6회
→ 100타/분 = 초당 2.7입력 = **입력당 약 220ms**. 달성 가능하나 여유 없음.

| 단계 | 측정 | 시점 |
|---|---|---|
| 기준선 | 한 손 + 표준 두벌식 키보드 = 40타/분 (페르소나 설정값) | 완료 |
| 웹 트레이너 | 실기 없이 배열만으로 도달 타수 | 하드웨어 완성 전 |
| 팀원 4인 30분 학습 | 초기 습득 속도, 오타율 | 시제품 완성 직후 |
| 시연 | 실제 문장 입력 + 웹 브라우징 (**드래그·조합 단축키 반드시 포함**) | 발표 |

발표에서는 "100타 달성"이 아니라 **학습곡선 초기 기울기**를 근거로 제시할 것.

### 4-5. 키맵 편집 도구

전용 프로그램 대신 **WebHID 기반 웹 페이지**(Vial/QMK Configurator 방식). 브라우저만으로 키맵 변경.
"설치 권한 없는 PC" 제약이 설정 단계까지 일관되게 유지된다. 같은 페이지에 배열 학습 트레이너를 붙인다.

## 7. 열려 있는 결정 / 미해결

1. **26키 예산에 맞는 한글·영문 키맵 설계** ← 현재 최대 공백. 이전 배열안(천지인/Half-QWERTY)은 전제가 달라져 재설계 필요
2. 토글 스위치 실제 품번 선정 — 3동작(위/누름/아래) 인식이 가능한 부품이 실제로 있는가, 작동력은 얼마인가
3. BANK 전환 힌지 + 복귀 스프링의 기구 설계 (4~5° 기울임, 오작동 방지 임계각)
4. XIAO nRF52840 Plus 기준 BOM 재산정 및 실견적
5. 펌웨어 담당자 지정 — 자모 상태머신이 전체 난이도의 절반
6. 블라인드 조작 전제에서 26키를 촉각만으로 구분하는 방법 (키캡 형상·질감 차별화)

**수요자 멘토링에서 확인해야 할 것**
- 기기 밀림 — 논슬립으로 충분한가, 클램프가 필요한가
- 손가락 관절의 방향 입력(위로 밀기/아래로 밀기)이 실제로 가능한가
- 스위치 작동력 상한 (1.0N이 타당한가)
- 오타 복구: Backspace 한 번이 자모 단위여야 하는가, 음절 단위여야 하는가
- 침대 프레임에 클램프를 물릴 수 있는가 (병원 침대 / 가정용 전동침대 / 일반 침대)
- 체위 변경 후 재정렬을 혼자 하셔야 하는가, 도움을 받으시는가

## 9. 작업 규칙

1. **하드웨어 사양의 근거는 항상 신청서 수정본이다.** 설계 md는 수정본과 충돌하지 않는 부분만 인용한다.
   (설계 md가 더 자세해서 최신처럼 보이지만, 실제로는 신청서 수정본이 뒤에 나왔다.)
2. **추정치를 확정값처럼 쓰지 않는다.** 모든 수치에 확신도 등급(높음/중간/낮음)을 붙인다.
3. 1차 자료(제조사 공식 스펙시트, 규제·표준 문서, 데이터시트) 없이 부품·수치를 단정하지 않는다.
   못 구했으면 "미확인"으로 표시하고 마케팅 카피로 빈칸을 메우지 않는다.
4. 발표·문서에서 Track A(문자 입력 특화)와 Track B(포인팅 특화, 화상 키보드 방식 10~20타/분)의
   **속도를 나란히 놓지 않는다.** 자릿수가 다르다.
5. 팀원 연락처·주소는 외부에 공개되는 산출물에 절대 넣지 않는다.
