| # | 신청서 내용 | 변경 | 이유 |
|---|---|---|---|
| 1 | 모디파이어(Shift/Space/Ctrl/Alt/Layer)를 **손바닥 반대편**에 배치, 엄지를 내려 누름 | **폐지.** 새끼손가락 5-way + 엄지 하단으로 재배치 | 그립 상태에서 반대편에 닿는 손가락이 없음. 엄지로 내리면 트랙볼을 놓아야 해서 드래그·Ctrl+클릭이 불가능 |

## 1. 설계 결함 2개와 해법

### 결함 A — 엄지 자원 충돌

예상도상 엄지가 담당하는 것: 트랙볼 조작 / 좌·우 클릭 / (아래로 내려) 모디파이어 5종.
엄지는 한 번에 한 곳에만 있으므로 다음이 전부 불가능합니다.

- **드래그**: 좌클릭을 누른 채 트랙볼을 굴려야 하는데, 같은 엄지가 둘 다 할 수 없음
- **Ctrl + 클릭**, **Shift + 클릭**: 모디파이어와 클릭이 동시에 안 됨
- 신청서 페르소나의 요구사항 "손을 떼지 않은 채로 **드래그**, **조합 단축키**를 모두 수행"과 정면 충돌

**해법 3종 (전부 적용)**

1. **드래그 락** — 좌클릭 더블탭 = 버튼 눌림 유지. 트랙볼로 이동 후 한 번 더 탭하면 해제.
   Kensington·Elecom 트랙볼에 이미 있는 검증된 기능이라 새 개념이 아님.
2. **원샷 모디파이어 (One-Shot Modifier)** — Ctrl을 탭하면 "다음 입력 1개에만" 적용되고 자동 해제.
   Ctrl+C, Shift+클릭이 순차 입력으로 해결됨. Windows 고정키(Sticky Keys)와 결과는 같지만
   **OS 설정을 건드리지 않고 펌웨어에서 처리**하므로 설치 권한 없는 PC 제약을 그대로 만족.
   더블탭하면 잠금(연속 적용), 세 번째 탭에 해제.
3. **모디파이어를 엄지에서 새끼손가락으로 이전** — 엄지는 포인팅 전담, 손가락은 문자·기능 전담으로 분리.

> 발표 포인트: "한 손 입력의 병목은 모드 전환 비용"이라는 팀의 문제 재정의는 옳지만,
> 예상도는 그 비용을 엄지 하나에 몰아넣어 오히려 늘리고 있었습니다. 자원을 분리하는 것이 수정 방향입니다.

### 결함 B — 한글 입력 경로 미정의

물리 입력은 20개(4손가락 × 5방향)인데 두벌식은 자모 26키 + 시프트 조합으로 33종이 필요합니다.
레이어로 나누면 음절마다 레이어를 오가야 해서, 페르소나의 "2주 내 실무 속도" 목표와 맞지 않습니다.

**해법: 천지인 파생 배열 + 멀티탭 제거** → §2, §3

## 2. 한글 입력 아키텍처 (핵심)

### 2.1 왜 두벌식 스캔코드로 변환해야 하는가

장치는 표준 HID 키보드입니다. PC의 한글 IME(Windows MS-IME, macOS 2벌식)는
**두벌식 스캔코드**를 기다리고 있습니다. 따라서 사용자가 어떤 방식으로 입력하든,
펌웨어는 최종적으로 두벌식 자모에 해당하는 스캔코드를 내보내야 합니다.

```
[5-way 입력]  →  [천지인 상태머신]  →  [자모 확정]  →  [두벌식 스캔코드]  →  [OS IME가 음절 조합]
   장치 안                                                        │
                                                        여기부터 표준 HID
                                                        드라이버·설치 권한 불필요
```

한/영 전환도 OS 기본 경로를 그대로 씁니다 (HID Usage `0x90 LANG1 / 한/영`, 또는 우측 Alt).
**장치는 IME를 흉내내지 않고, IME에게 두벌식으로 말을 겁니다.** 이것이 "드라이버 불필요"의 실제 근거입니다.

### 2.2 확정 지연 (Commit Delay) — 백스페이스 회수를 쓰지 않는 이유

천지인은 `ㅣ + ·` = ㅏ 인데, 여기에 `·`가 하나 더 오면 ㅑ가 됩니다.
ㅏ에 해당하는 `k`를 이미 보냈다면 백스페이스로 회수 후 `i`를 다시 보내야 하는데,
IME 조합 중 백스페이스의 동작(자모 단위 / 음절 단위)이 OS마다 다릅니다.

→ **모음이 확정될 때까지 스캔코드 방출을 보류**합니다.
다음 자음이 입력되거나 유휴 시간(기본 400ms, 조정 가능)이 지나면 확정해 한 번에 방출.
실사용에서는 다음 자음 입력이 곧바로 오므로 체감 지연이 거의 없고, 백스페이스 회수가 불필요합니다.

> 확신도: 설계 타당성 **높음** / OS별 IME 실측은 **미검증** — §6 D-day 1 최우선 검증 항목

### 2.3 천지인을 고른 이유

- 47세 한국인 사무직 페르소나에게 **이미 손에 익은 배열**입니다. "완전히 새로운 키 배열을 외우는 부담"이라는
  페르소나의 제약 조건을 정면으로 해소합니다.
- 2011년 3월 방송통신위원회가 피처폰 한글자판 단일 국가표준으로 확정했고, 2014년 7월 ITU 국제표준으로 채택됐습니다.
  **공적 표준을 계승했다**는 점은 국립재활원 심사에서 근거로 쓸 수 있습니다. (확신도: **중간** — 언론 보도 교차확인, 표준 문서 원문 미확인)
- 12키로 한글 전체를 표현하도록 설계된 방식이라, 20입력 예산에 여유를 두고 들어갑니다.

### 2.4 딸깍이 천지인에서 개선하는 점

| 천지인(휴대폰) | 딸깍 | 효과 |
|---|---|---|
| `ㄱ→ㅋ→ㄲ` 같은 키 반복 탭으로 순환 | **획추가 키를 선행 탭** (0회/1회/2회) | 반복 탭 타임아웃과 모호성 제거 |
| `ㄴㄹ`, `ㅇㅁ`, `ㅅㅎ` 가 한 키에 묶여 멀티탭 필요 | **ㄴ ㄹ ㅇ ㅁ ㅅ ㅎ 전부 전용 입력** | 자음 14개 중 10개가 1타 |
| 손가락이 키패드 위를 이동 | 손가락 **이동 없음**, 관절 방향만 | 편마비·근력저하 사용자 부하 감소 |

## 3. 키맵

### 3.1 물리 입력 예산 (총 25)

| 부위 | 입력 | 개수 |
|---|---|---|
| 검지·중지·약지·새끼 | 5-way 스위치 (누름/위/아래/좌/우) | 20 |
| 엄지 상단 | 트랙볼 (X/Y) | (아날로그) |
| 엄지 하단 | 좌클릭 · 우클릭 · Space 패들 | 3 |
| 손바닥 측면 | 대형 패들 1 (Enter 기본, 재할당 가능) | 1 |
| 외부 | 3.5mm 스위치 잭 | 2 (확장) |

### 3.2 Layer 0 — 한글 (기본)

| | **누름** | **위** | **아래** | **좌** | **우** |
|---|---|---|---|---|---|
| **검지** | `·` | Space | `ㅡ` | `ㅣ` | `·` |
| **중지** | ㄱ | ㄴ | ㄷ | ㅅ | ㅈ |
| **약지** | ㅂ | ㅇ | ㅁ | ㄹ | ㅎ |
| **새끼** | Enter | **획추가**(OSM) | Backspace | **Ctrl**(OSM) | **Layer** |

- 검지 `누름`과 `우`에 `·`를 **중복 배치**한 것은 의도적입니다. ㅑ·ㅕ·ㅛ·ㅠ 처럼 `·`를 연타하는 모음에서
  같은 스위치 연타 대신 **교대 입력**이 가능해 속도가 올라갑니다.
- 엄지 Space 패들과 검지 `위` Space도 중복입니다. 손 상태에 따라 편한 쪽을 쓰게 합니다.

**자음 14개 커버 확인**

| 기본 (1타) | ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅅ ㅇ ㅈ ㅎ | 10 |
|---|---|---|
| 획추가 1회 (2타) | ㅋ(ㄱ) ㅌ(ㄷ) ㅍ(ㅂ) ㅊ(ㅈ) | 4 |
| 획추가 2회 (3타) | ㄲ ㄸ ㅃ ㅆ ㅉ | 5 |

**모음 21개** — 천지인 조합으로 전수 생성. 예: `ㅏ = ㅣ·` / `ㅑ = ㅣ··` / `ㅓ = ·ㅣ` / `ㅕ = ··ㅣ` /
`ㅗ = ·ㅡ` / `ㅛ = ··ㅡ` / `ㅜ = ㅡ·` / `ㅠ = ㅡ··` / `ㅐ = ㅣ·ㅣ` / `ㅚ = ·ㅡㅣ` / `ㅢ = ㅡㅣ`

**한/영 전환** — Layer 키 더블탭 → `LANG1` 방출 (OS 기본 IME 토글)

### 3.3 Layer 1 — 영문

빈도순 상위 20자를 20입력에 1타 직결, 하위 6자는 획추가 선행 2타.

| | **누름** | **위** | **아래** | **좌** | **우** |
|---|---|---|---|---|---|
| **검지** | e | t | a | o | i |
| **중지** | n | s | r | h | l |
| **약지** | d | c | u | m | f |
| **새끼** | Enter | 획추가(OSM) | Backspace | Ctrl(OSM) | Layer |

2타(획추가 선행): `p g w y b v k x j q z` → 검지·중지·약지 15슬롯에 배치
대문자: Shift(엄지 하단 조합 또는 획추가 롱프레스) 원샷

> 영문은 페르소나 업무(문서·메일)에서 비중이 낮아 2타를 허용했습니다.
> 대신 학습 부담을 줄이도록 §5의 웹 트레이너를 제공합니다.

### 3.4 Layer 2 — 숫자·기호·기능

숫자 0–9, `. , - / @ ( )`, 방향키, Tab, Esc, F1–F12, 커서 감도 단계 조절.

### 3.5 포인팅 컨텍스트

- 좌클릭 · 우클릭: 엄지 하단 (기본)
- 드래그: 좌클릭 더블탭 = 드래그 락
- 스크롤: Layer 홀드 + 트랙볼
- 감도: 3단 구간 선형 근사로 비선형 곡선 구현. 저속 구간 정밀 조준, 고속 구간 화면 횡단.
  Layer 2에서 5단계 조정, 설정은 플래시에 저장.

## 4. 기구 설계

| 항목 | 값 | 근거 |
|---|---|---|
| 그립 각도 | **65°** | 상용 버티컬 마우스 55~60°보다 세움. 편마비 사용자의 회내 저항을 더 줄이기 위함 (확신도 중간, 멘토링 검증 필요) |
| 외형 | 폭 65 × 깊이 110 × 높이 95 mm | 손 길이 175~195mm 성인 남성 기준(중형 셸) |
| 셸 | 소·중·대 3종 교체형 | 신청서 명시 사항 유지 |
| 트랙볼 | **25mm** (대형 셸은 34mm 옵션) | M575 등 엄지 트랙볼 표준은 34mm이나, **근력 저하 사용자에게는 작고 가벼운 볼이 유리**. 관성이 작아 정지 제어가 쉬움 |
| 볼 지지 | 2.5mm 세라믹 BTU 3점 | DIY 트랙볼 표준 구성 |
| 손가락 스위치 배치 | R28mm 원호 상 18mm 피치 4개 | 손가락 끝 자연 궤적 |
| 스위치 작동력 | **1.0N 이하** 선정 | 표준 5-way 택트는 1.6N. 근력 저하 사용자 기준으로 낮춰야 함 |
| **총중량** | **≥ 250g** (하부 웨이트 삽입) | ⚠️ 아래 참조 |
| 베이스 | 실리콘 논슬립 + **책상 클램프/벨크로 옵션** | ⚠️ 아래 참조 |

> ⚠️ **한 손 사용자 고유 요구 — 신청서에 없던 항목**
> 양손 사용자는 반대 손으로 기기를 붙잡을 수 있지만, 한 손 사용자는 그럴 수 없습니다.
> 스위치를 미는 방향 입력은 기기를 옆으로 밀어내는 반력을 만들므로, **기기가 절대 밀리면 안 됩니다.**
> 자중·마찰만으로 부족하면 클램프가 필요합니다. → **오늘 수요자 멘토링에서 반드시 물어볼 것.**

## 5. 전자 · 펌웨어

### 5.1 MCU 선택

신청서대로 **ESP32-S3 유지**를 권고합니다.

| 근거 | 내용 |
|---|---|
| 팀 경험 | 전원이 ESP32 기반 PCB 설계·시제품 완주 경험 보유 |
| USB HID | ESP32-S3는 USB OTG 내장 → TinyUSB로 네이티브 복합 HID (드라이버 불필요 요건 충족) |
| BLE | 같은 칩에서 확장 범위 커버. RP2040은 BLE 불가 |
| 일관성 | 제출한 신청서와 동일 |

**리스크**: QMK/ZMK 같은 기성 키보드 펌웨어가 ESP32-S3를 정식 지원하지 않아, 원샷 모디파이어·
드래그 락·포인팅 디바이스를 직접 구현해야 합니다.
**완화**: QMK의 `drivers/sensors/pmw33xx` 및 OSM 구현을 참조 이식합니다. 각 100줄 내외이고,
결과물을 GPL로 공개할 예정이므로 라이선스 문제가 없습니다.

### 5.2 구조

```
firmware/
├── input/
│   ├── trackball.c    PMW3610 SPI 버스트 리드 → 1kHz 리포트
│   ├── matrix.c       5-way ×4 + 클릭 3 + 패들 1, 5ms 스캔 / 8ms 디바운스
│   └── extjack.c      3.5mm 외부 스위치 2ch
├── engine/
│   ├── ime_hangul.c   ★ 천지인 상태머신 → 자모 확정 → 두벌식 스캔코드 (확정 지연 버퍼)
│   ├── ime_latin.c    빈도 배열 + 획추가 2타
│   ├── layer.c        레이어 스택 / 원샷 모디파이어 / 드래그 락
│   └── accel.c        3구간 선형 근사 감도 곡선
├── hid/
│   ├── usb_hid.c      TinyUSB — Keyboard + Mouse + Consumer 복합 디바이스
│   └── ble_hid.c      NimBLE HID over GATT (확장)
└── config/keymap.c    기본 키맵 + NVS 저장
```

`ime_hangul.c`가 전체 난이도의 절반입니다. **여기에 가장 잘하는 사람을 배치하세요.**

## 7. 오늘(8/8) 워크숍에서 결정할 것

**팀 합의 필요**

1. 손바닥 반대편 5키 폐지에 동의하는가 (§1 결함 A)
2. 천지인 파생 배열 채택 vs 두벌식 레이어 방식 (§2.3)
3. 필수 범위에서 BLE를 뺄 것인가 — 뺀다면 USB 완성도에 인력 집중 가능
4. `ime_hangul.c` 담당자 지정

**수요자 멘토링에서 물어볼 것**

1. 기기가 밀리는 문제 — 논슬립으로 충분한가, 클램프가 필요한가 (§4 ⚠️)
2. 손가락 관절의 **방향** 입력(밀기/당기기)이 실제로 가능한가 — 편마비 사용자의 손가락 분리 운동 가능 범위
3. 스위치 작동력 상한은 얼마인가 (1.0N이 타당한가)
4. 천지인을 실제로 쓰고 있는가 — 안 쓴다면 배열 전제가 무너짐
5. 오타 복구 방식: Backspace 한 번이 자모 단위여야 하는가, 음절 단위여야 하는가

## 8. 검증 계획 — "분당 100타"를 어떻게 증명하나

한국 타자 검정의 '타'는 자모 1타입니다.
- 한글 1음절 ≈ 자모 2.7개
- 딸깍 기준 자모 1개당 평균 입력 ≈ 1.6회 (모음 2~3입력, 자음 대부분 1입력)
- 100타/분 = 초당 1.67자모 = **초당 2.7입력 = 입력당 약 220ms**

손가락 이동 없는 5-way 방향 조작은 150~250ms가 현실 범위이므로 **달성 가능하나 여유가 없습니다.**
발표에서는 "100타 달성"이 아니라 **학습곡선 초기 기울기**를 근거로 제시하는 편이 안전합니다.

| 단계 | 측정 | 시점 |
|---|---|---|
| 기준선 | 한 손 두벌식 표준 키보드 = 40타/분 (페르소나 설정값) | – |
| 웹 트레이너 시뮬레이션 | 실기 없이 배열만으로 도달 타수 측정 | 하드웨어 완성 전 |
| 팀원 4인 30분 학습 | 초기 습득 속도, 오타율 | 시제품 완성 직후 |
| 시연 | 실제 문장 입력 + 웹 브라우징 (드래그·Ctrl+C 포함) | 발표 |

**시연 시나리오는 반드시 드래그와 조합 단축키를 포함하세요.** §1 결함 A를 해결했다는 증거가 그것뿐입니다.
