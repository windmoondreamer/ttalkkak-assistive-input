## 0. 실행 방식 — 왜 피처를 지우고 다시 만들지 않았는가

Onshape `POST /features` 는 트리 **최하단에만** 추가한다. 중간 삽입이 없다.
front trim 은 blank 와 union 사이에 있어야 하므로, 삽입을 하려면 기존 파이프라인
전체(약 30개 피처)를 지우고 다시 쌓아야 한다.

대신 **Feature Studio 소스를 고치면 기존 인스턴스가 전부 자동 재생성된다**는 성질을 썼다.

| 필요한 변경 | 실행 방법 |
|---|---|
| I1~I4 축을 F2 로 | FS 의 `IDX` 상수 교체 → 모든 stage 자동 반영 |
| front trim 단계 추가 | **`GROOVE` stage 를 front trim 으로 전환** (트리 위치가 이미 blank~union 사이) |
| 개별 retainer plug 폐기 | `RETAINER` stage 를 no-op 으로 |
| front lip 0.8 → 1.5 | FS 상수 `LIP_F2` (§0.1 참조) |

- enum 식별자 `GROOVE` / `RETAINER` 는 **기존 feature JSON 호환을 위해 유지**했고,
  표시명만 `E3 front trim` / `G unused (retired)` 로 바꿨다.
- **stage 단위로 바뀌므로 feature ID 를 추측할 필요가 없다.** 해당 stage 인스턴스만 정확히 변한다.
- 각 stage 는 여전히 **버튼 1개, target = 그 blank 하나뿐**이다. 쉘은 negative target 이 아니다.

### 0.1 `#finger_switch_front_lip` — FS 상수로 처리한 이유

트리 변수 피처를 수정하려면 그 featureId 가 필요하고, 그러려면 `GET /features` 가 필요하다.
이 엔드포인트가 **429 (Retry-After ≈ 10,363 s ≈ 2.9 시간)** 라 접근할 수 없었다.

→ FS 안에 `const LIP_F2 = 1.5 * millimeter;` 로 두고 `getVariable` 대신 사용했다.
**형상은 승인값 1.5 mm 로 정확히 만들어졌다.** 트리 변수 `#finger_switch_front_lip`(0.8)은
현재 아무 데서도 읽히지 않는 사문(死文)이다.
**후속 정리 항목:** rate limit 해제 후 트리 변수를 1.5 로 바꾸고 `getVariable` 로 되돌린다.

### 0.2 컴파일 실패 1회와 원인

첫 업로드에서 `featureSpecs` 가 비었다(컴파일 실패). 원인은
**RETAINER 를 no-op 으로 만들면서 `const clr` 이 미사용이 된 것**이다.
FeatureScript 는 **미사용 지역변수를 경고가 아니라 에러로 처리한다.**
해당 선언을 지우자 즉시 컴파일 성공(`idxHolderAtomic`).

## 3. HOLD 조건 3건 — 실물 검증에서 드러난 것

형상 재생성 자체는 성공했지만, **설계 위치가 아니라 실제 실현 위치**로 재평가하면
승인 기준 3개가 미달한다. §5·§13·§14 의 HOLD 지시에 따라 **여기서 중단하고 보고한다.**

### HOLD-1. 스위치가 설계보다 깊게 들어가야 한다 → 여유 1.200 → **1.145 mm**

**현상.** 6 × 6 단면을 축을 따라 훑으면 설계 앞면 깊이 4.5 mm 에서 아직 재료가 남아 있다.

| 깊이(mm) | 4.50 | 4.60 | 4.70 | 4.80 | 4.90 | 5.00 | 5.10 | 5.20 |
|---|---|---|---|---|---|---|---|---|
| I1 | 22 | 2 | 1 | 1 | **0** | 0 | 0 | 0 |
| I2 | 33 | 1 | **0** | 0 | 0 | 0 | 0 | 0 |
| **I3** | 42 | 7 | 5 | 4 | 3 | 2 | 1 | **0** |
| I4 | 30 | **0** | 0 | 0 | 0 | 0 | 0 | 0 |

(169개 표본 중 재료와 겹치는 점 수. 0 이 되는 깊이가 실제 최소 착좌 깊이)

→ **실제 착좌 깊이 = I1 4.90 / I2 4.70 / I3 5.20 / I4 4.60 mm** (설계 4.50)

**원인.** 막는 재료는 홀더가 아니라 **기존 8 × 8 개구부 바깥의 쉘 벽**이다.
n0 국소좌표 y0 = −4.10 (개구부 경계 바로 바깥)에서 벽을 관통 측정하면:

```
y0 = -4.10, x0 = -2.74  ->  재료 [0.92 , 4.10]  두께 3.18 mm
y0 = -4.10, x0 = -1.29  ->  재료 [0.64 , 3.80]  두께 3.16 mm
y0 = -4.10, x0 =  0.00  ->  재료 [0.50 , 3.62]  두께 3.12 mm
y0 = -3.50, x0 =  0.00  ->  재료 [2.80 , 3.68]  두께 0.88 mm   ← 개구부 안: 홀더 lip (정상)
```

그립이 볼록하므로 개구부 바깥으로 갈수록 **외피가 내려앉아** 벽의 안쪽면이
n0 깊이 **3.62 ~ 4.10 mm** 까지 내려온다. 축을 16.5° 기울이면 스위치 앞면의 한쪽 모서리가
그 영역으로 올라가 걸린다. (t=0 이었을 때는 앞면이 벽과 평행해 생기지 않던 문제다)

**결과.** 실제 착좌 위치 기준 SAT 최소 여유 **1.145 mm** (요구 ≥ 1.20).

> **docs/13 의 모델 결함:** front lip 제약을 "n0 깊이 ≥ 트림면 2.8 + 0.5" 로 걸었는데,
> 실제 기준면은 평평한 2.8 이 아니라 **곡률로 최대 4.10 까지 내려오는 쉘 안쪽면**이다.

### HOLD-2. 포켓 칸막이 **0.648 mm** (승인 0.80, HOLD 조건 < 0.80)

§2-D 참조. 원인은 **칸막이를 스위치(6.0)가 아니라 포켓(6.4 × 6.4 × 6.2)으로 구속했어야**
하는데 그러지 않은 것이다. 포켓이 스위치보다 뒤로 0.2 mm 더 길고, 그 뒷부분이
축이 더 수렴하는 구간에 들어가 최근접점이 된다.

F2 축을 유지한 채 앞면 깊이만 바꿔도 해소되지 않는다:

| 앞면 깊이 | 스위치 최소 여유 | 칸막이 최소 |
|---|---|---|
| **4.5 (설계)** | **1.200** | **0.648** |
| 5.0 | 1.062 | 0.567 |
| 5.2 | 1.006 | 0.511 |
| 6.0 | 0.872 | 0.317 |

깊게 넣을수록 나빠진다. **축을 다시 풀어야 한다.**

### HOLD-3. I4 홀더 ↔ 나사 B **2.27 mm** (요구 ≥ 2.5)

§2-G 참조. 축 문제가 아니라 **홀더 후단 깊이**(12.5 → 13.2)가 원인이며,
개별 plug 폐기로 불필요해진 `#finger_retainer_thickness`(2.5 mm) 예비를 줄이면 해소된다.
**blankTo = 11.7 mm → 나사 B 여유 3.60 mm** (기준선 2.89 보다 오히려 개선).

이 항목은 **축과 무관한 독립 수정**이며 위험도가 낮다.

### 수정안 ①: 칸막이를 **포켓 기준**으로 다시 구속 (HOLD-2)

제약을 `포켓(6.4×6.4×6.2) 최소거리 ≥ 0.80` + `스위치 ≥ 1.20` + `분할벽 ≥ 1.5` 로 두고
자유축 minimax 를 다시 풀면:

| 앞면 깊이 | 최대 편차 | 칸막이 | 스위치 여유 | 분할벽 | I4 편차 |
|---|---|---|---|---|---|
| **4.5** | **17.12°** | **0.800 mm** | **1.347 mm** | 1.50 mm | **0.00°** |
| **5.0** | **17.17°** | **0.800 mm** | **1.348 mm** | 1.50 mm | **0.00°** |

**F2 의 16.46° 대비 +0.66° 로 칸막이 0.648 → 0.800 mm 를 회복한다.**
스위치 여유도 1.200 → 1.347 mm 로 함께 올라간다 (칸막이 구속이 더 강한 조건이기 때문).

> **중요:** 축을 다시 풀면 **앞면 깊이를 4.5 → 5.0 으로 옮겨도 편차가 0.05° 밖에 안 는다.**
> 즉 HOLD-1(착좌 깊이)과 HOLD-2(칸막이)를 **한 번의 재최적화로 동시에 해결할 수 있고,
> 개구부를 건드릴 필요가 없다.** 앞면 깊이는 새 축에 대해 착좌 깊이를 실측한 뒤 확정한다.

### 수정안 ②: 홀더 후단 깊이 축소 (HOLD-3)

```
현재:  blankTo = seatTo + #finger_retainer_thickness(2.5) = 13.2 mm  -> 나사 B 2.27 mm
제안:  blankTo = seatTo + 1.0                            = 11.7 mm  -> 나사 B 3.60 mm
```
스위치 뒷면 10.5 / seat 끝 10.7 이므로 후면 여유 1.0 mm 는 충분하다.
개별 plug 를 폐기했으므로 2.5 mm 예비는 근거가 없어졌다.
**축·여유·칸막이에 영향 없는 독립 수정.**

### 수정안 ③: 착좌 깊이 — **재최적화에 흡수된다 (개구부 수정 불필요)**

쉘 + 기존 8×8 개구부만 있는 상태(홀더 없음 = 축 후보 평가의 올바른 기준)에서
6 × 6 스위치가 재료와 겹치지 않는 최소 깊이를 실측하면:

| 축 | I1 | I2 | I3 | I4 | **필요 앞면 깊이** |
|---|---|---|---|---|---|
| F2 (현재 CAD) | 4.75 | 4.70 | 5.15 | 4.30 | **5.15 mm** |
| 수정안 축 | 4.60 | 4.75 | 5.25 | 4.30 | **5.25 mm** |

앞면 깊이를 5.3 mm 로 두면 충족되고, 그 깊이에서 재최적화한 축은:

| 앞면 5.3 (lip 2.3) | 값 |
|---|---|
| 최대 편차 | **17.21°** |
| 칸막이 | **0.800 mm** |
| 스위치 여유 | **1.348 mm** |
| 분할면 벽 | 1.50 mm |

```
I1 = (-0.851033, -0.500047, -0.160298)
I2 = (-0.393870, -0.571110, -0.720208)
I3 = (-0.069850, -0.997555, +0.002429)
I4 = (+0.024161, -0.968017, -0.249718)
```

→ **HOLD-1 · HOLD-2 가 한 번의 재최적화로 동시에 풀린다.**
→ **`INDEX_openings` 를 건드릴 필요가 없다** (§3 지시 유지 가능).
→ 대가는 F2 대비 **최대 편차 16.46° → 17.21° (+0.75°)** 와
   **`#finger_switch_front_lip` 1.5 → 2.3 mm** 뿐이다.

### (참고) 개구부를 고치는 안 — 채택 불필요

당초 후보였던 "캡 포켓 아래 국소 릴리프 추가"는 위 재최적화로 **불필요해졌다.**
개구부·캡 외형은 그대로 둔다.
